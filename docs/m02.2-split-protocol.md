# CET433 M02.2 split and evaluation protocol

## Feature identity `cet433-exact-groups-v1`

The schema is the manifest's ordered list of 42 model features. IDs and both
targets are excluded. Grouping uses parsed values before any learned
preprocessing. Numeric fields are converted to binary64 in the safe integer
range, encoded using hexadecimal float strings, and normalize both signed
zeros to zero. Infinite and out-of-range numeric values are rejected. Text
fields preserve case, whitespace, and Unicode code points. Missing values
become JSON null, distinct from any literal string. The policy name, column
order, and normalized tuple are serialized as compact ASCII JSON and hashed
with SHA-256. Exact tuple equality determines membership and a reverse lookup
rejects a digest shared by distinct tuples. Fingerprints identify exact model
inputs under this contract. They do not establish session or capture identity.

Every source observation is retained. Conflicting binary or attack-family
targets stay in one group with their original labels. Repeated observations
therefore retain their original influence on fitting and reporting.

## Assignment and model selection

Generate five stratified group candidates within the official training
partition with seed 42. Rank candidates by deviation from the 20% validation
target plus mean class-wise deviation from 20%, breaking ties by fold order.
Choose the first candidate whose fit and validation both contain all classes
and whose fit permits five grouped CV folds with all classes on both sides of
every fold. The acceptance floor is nonzero support for both binary classes and
every observed attack category. Treat low support as a precision limitation.

The saved assignment binds the original row order to the training SHA-256.
Each ASCII position is `V` for validation or `0` through `4` for the inner
held-out CV fold. Record the seed, software versions, assignment digest, and
class and group support. The notebook passes the already grouped assignments
to tuning through `PredefinedSplit` in fit-row order, using the full fit set.
The former 30,000-row cap is retired in this policy.
MLP is deferred because its internal early-stopping split does not accept a
group assignment. Random Forest and LightGBM retain fold-local preprocessing.
No model fit is needed to generate or audit the split plan.

## Final reporting `cet433-eval-v1`

- Freeze model choices and operating threshold using training and validation
  only. Assess joint feasibility across the distinct validation score
  boundaries for recall ≥95% and FPR <1%. Among feasible thresholds choose
  minimum documented estimated cost, then lower FPR, then higher threshold.
  If infeasible, record that explicitly. The lowest-cost validation threshold
  under the same tie-break serves as a descriptive benchmark.
- Score the original official test observations once at the frozen threshold.
  Report the raw official aggregate and the exact-feature-unseen stratum
  relative to the final internal fit observations. Include row counts, binary
  support and prevalence, category support, and per-category recall. Report
  unavailable metrics explicitly for empty or single-class strata.
- Label any future deduplicated sensitivity analysis with its exact key and
  support. Its metrics describe a different weighted population and must
  remain separate from the raw official benchmark.
- Keep official test outcomes out of threshold and model selection. The
  supplied partition files lack documented event timestamps and capture IDs.
  Exact input group isolation does not establish chronological isolation or
  independence of related flows.
