## Reproduce and qualify the environment after approval

Use a network-enabled disposable Linux x86_64 space with CPython 3.13.18
available. Resolve for the desired platform, with wheels and hashes:

```sh
uv pip compile --python-version 3.13.18 --python-platform x86_64-manylinux_2_28 \
  --only-binary=:all: --generate-hashes environment/colab-py313-v1.in \
  -o environment/colab-py313-v1.lock
sha256sum environment/colab-py313-v1.lock

python3.13 -m venv .venv
.venv/bin/python -m pip install --only-binary=:all: --require-hashes \
  -r environment/colab-py313-v1.lock
.venv/bin/python -m pip check
.venv/bin/python -B environment_smoke.py
```

Use a fresh environment or a path matched by the repository environment
ignore rule, such as `.venv/`. Store the lock, its digest, resolver version,
and output of `pip check` and the smoke test alongside the verified source
digest. The strict smoke test checks target Python minor version, ABI,
platform, glibc, direct and transitive pins, imports, and an in-memory joblib
round trip. It does not fit models or invoke a SHAP explanation.
`--diagnose` inventories the current runtime and reports individual failures
without qualifying it.

For a self-managed notebook resolve the optional profile to its own
hash-pinned lock with the same resolver flags. In that isolated environment
run `python -m pip check`, verify `import IPython, ipykernel, jupyter_client,
zmq`, and register the new kernel with `python -m ipykernel install --user
--name cet433-py313`. Treat any differences between resolved pins and the
candidate as review items. Do not install the self-managed kernel profile
into the managed Colab session.

## Recovery

If imports fail in a disposable qualification environment, keep its logs
and recreate the isolated environment from the recorded lock. If a managed
runtime is broken, save needed runtime-only evidence outside the VM first,
then use **Runtime → Disconnect and delete runtime** in Colab to restore a
fresh managed VM. This discards its ephemeral runtime state. Reconnect,
remount Drive, and verify the snapshot and dataset digests again. The Drive
copies of the prior snapshot, datasets, and assignment should be preserved.
Use the previously verified notebook and snapshot together if the new
bootstrap cannot run. [Google Colab reset documentation](https://research.google.com/colaboratory/faq.html#reset-runtime).
