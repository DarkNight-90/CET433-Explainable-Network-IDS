## Integrity policy and independent calculations

- Require the qualified isolated CPython 3.13.18 runtime, the recorded lock,
  installed package versions, and Agg. The smoke check verifies the SHAP pin
  via distribution metadata.
- Compare the manifest with the authenticated digest and the pinned reviewed
  snapshot and base revision. Check exactly three approved model entries,
  fit attempts and completed fit reports, the validation JSONs, the selected
  tree record, and the unopened-test declaration. Verify all artifact
  hashes before loading any model. For deserialization, hash the exact
  in-memory bytes passed to `joblib.load` again.
- Verify the manifest hashes, exact training checksum and saved M02.2 assignment
  bytes and codes. Check the verified group support and overlap against the run
  and use the saved validation positions in CSV order. The partition contains
  35,068 rows, including 23,868 attacks and 11,200 normal flows.
- Apply `predict_proba` only to the frozen validation frame. Calculate
  ROC-AUC and confusion-derived metrics at 0.5 and the existing saved
  threshold. Confusion counts and cost are compared exactly, with absolute
  tolerance `1e-12` for floating metrics.
- Independently accumulate descending score-bucket counts, preserving tied
  scores and including endpoints 0 and 1. Use integer comparisons for
  FP ≤111 and FN ≤1,193. Report maximum recall under the strict FPR cap
  and minimum FPR under the recall floor. A point is feasible only when
  both hold. Compare the saved threshold's ranking key against the
  minimum key among feasible points, or among all points when none are
  feasible. The key is (5 × FP + 120 × FN, FP, −threshold). Fixed negative
  support makes FP ordering identical to FPR ordering. Report only the
  comparison and the already recorded operating points.
- Preprocessing diagnostics inspect the fitted encoder and apply only its
  existing transformer on validation group representatives. Collision
  counts describe exact equality of transformed vectors within this
  validation set. They do not demonstrate session independence or quantify
  the impact of changing the preprocessing.

## Diagnostic output

The single report is
`MyDrive/CET433_Explainable_IDS/audits/<audit-id>/inference_audit.json`.
The ID must be unused. All files under `runs/m03-stage-a-001/` are read-only
inputs to the utility. Keep the run and audit records separate.

| Section | Contents |
|---|---|
| Provenance | Audit schema and code version/hash, authenticated manifest hash, Stage A snapshot hash and source revision, lock hash, recorded fit count and test status |
| Validation identity | Raw-row and group supports, dataset and split hashes, and a digest over ordered positions, group IDs and labels |
| Per model | Model hash, verified fit journal result, ROC-AUC, metrics at 0.5 and the saved threshold, mismatch fields and independent feasibility evidence |
| Diagnostics | Aggregate FP counts and FPR by protocol, service and state, FN and recall by family, size buckets, mixed-label groups, error concentration, encoder coverage, and transformed collisions |

A successfully computed disagreement produces a report with
`record_matches: false` and exit status 1. An integrity or runtime failure
stops the audit. A failure after directory reservation can leave an empty
or incomplete audit directory. Preserve it and use a fresh ID for an
authorized retry. The report carries no row-level flows, scores, or group
identifiers.
